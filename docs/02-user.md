# 주 사용자 — 첫 아이의 부모

> 🔴 **처음에는 "다섯 살 아이를 둔 부모"였다.** 서비스가 임신 때부터 초등 저학년까지를
> 다루게 되면서 **범위가 한 시점에서 한 구간으로 넓어졌다.**
>
> 그래서 먼저 판정했다 — **한 명으로 묶을 수 있는가?**
> **묶인다. 임산부와 초등 부모는 다른 사람이 아니라 같은 사람의 8~9년이기 때문이다.**
> 첫 아이를 가진 사람은 임신 중이었다가 → 신생아 부모가 되고 → 어린이집 그림을 받는다.
> 이건 세그먼트가 아니라 **한 사람의 타임라인**이다.

## 프로필

| | |
|---|---|
| **연령대** | **33세.** 첫 아이 |
| **역할** | 아이에게서 나온 실물을 받는 사람이자 **버리는 결정을 하는 사람** |
| **기기** | 🔴 **스마트폰, 세로, 한 손** |
| **사용 상황** | **손에 실물이 들려 있고 어디 둬야 할지 모르는 순간.** 산부인과 복도에서 초음파 사진을 받아 나올 때, 아이가 그림을 내밀 때. 다른 손엔 가방이 들려 있고 **쓸 수 있는 시간은 30초 남짓** |
| **빈도** | 시기마다 다르다 — 임신 때는 검진마다, 유아기에는 주 1~2회. **정해진 날이 아니라 손에 들어오는 날** |

## 🔴 이 사람의 시간표 — 중심에 둘 시기를 하나 정한다

| 시기 | 들어오는 것 | 밀도 |
|---|---|---|
| 임신 | 초음파 사진 | 검진 주기 |
| 영아 | 배냇저고리 · 손도장 | 산발 |
| **유아** | **그림 · 만들기** | **주 1~2회 — 가장 높다** |
| 초등 저학년 | 그림 · 상장 | 학기 단위 |

**중심은 유아다.** 밀도가 가장 높고, 실물이 가장 빨리 쌓이고,
*"버리려고 기록한다"*가 가장 날카롭게 성립한다 — 초음파 사진은 몇 장이지만 **그림은 상자를 채운다.**

**임신·영아 구간은 입구다.** 첫 아이를 가진 사람이 이 서비스를 처음 만나는 지점이고,
거기서 시작하면 **그림이 쏟아지는 시기에 이미 여기 와 있다.**
넓힌 이유가 *"더 많은 사람"*이 아니라 *"같은 사람을 더 일찍"*이다.

## 핵심 과업 (Job to be Done)

> **아이가 남긴 것을 잃지 않으면서, 집에 쌓이는 실물을 정리하고 싶다.**

이 과업은 **두 개가 붙어 있다.** 보관과 정리는 보통 반대 방향인데, 이 사용자에게는 하나다.
**정리하려면 먼저 남겨야 하고, 남겨야 버릴 수 있다.**

## 페인 3가지

**① 버릴 때 죄책감이 든다**
아이가 자랑스럽게 내민 것을 버리는 일이다. 그런데 물리적으로 다 보관할 수 없다.
→ **결국 아이 몰래 버리게 되고, 그 방식이 계속 불편하다.**

**② 찍어둬도 다시 못 찾는다**
폰으로 찍긴 하는데 일상 사진들 사이에 섞인다. 몇 달 뒤에 찾으려면 갤러리를 한참 스크롤해야 한다.
→ **찍는 행위가 보관으로 이어지지 않는다.**

**③ 🔑 물건만 남고 말이 사라진다 — 가장 크고, 유일하게 되돌릴 수 없는 손실**
아이는 그림을 내밀면서 반드시 말한다. *"이건 아빠가 자는 거야."*
그 말은 그림에 안 적혀 있고 **그 자리에서 안 물어보면 영영 얻을 수 없다.**
1년 뒤에 그림만 보면 무엇을 그린 건지 부모도 모른다.

🔴 **말을 하는 사람이 시기마다 다르다.** 태아는 말을 하지 않고, 아기도 한동안 안 한다.
그 시기에 남는 말은 **부모가 그 자리에서 한 말**이다 — 산모수첩이 하는 일이 그것이고,
**그것도 그 자리에서 안 적으면 사라진다.** 손실의 성질은 같고 말의 주인만 바뀐다.

## 게인 3가지

1. **버려도 괜찮다는 확신** — 남겼다는 것이 눈으로 확인되면 실물을 정리할 수 있다
2. **한 곳에 모여 있다는 것** — 흩어지지 않고, 시간순으로, 다시 찾을 수 있게
3. **손에 잡히는 결과물** — 한 해가 끝나면 한 권. 아이에게 보여줄 수 있고 부모님께 드릴 수도 있다

## 💡 의외의 발견

> **이 사람은 "보관하려고" 앱을 여는 게 아니다. "버려도 된다는 허락"을 받으려고 연다.**

기록 앱은 보통 *"많이 모을수록 좋다"*를 전제한다. 이 사용자는 반대다 —
**저장이 끝이 아니라 실물을 정리하는 것이 끝이다.**

**제품 판단에 미치는 영향 (실제로 화면이 달라진다):**

| | 보통의 기록 앱 | 이 서비스 |
|---|---|---|
| 등록 후 문구 | "저장되었습니다" | **"이제 원본은 정리하셔도 됩니다"** |
| 성공 지표 | 저장 개수 | **실물을 버릴 수 있었는가** |
| 강조하는 것 | 쌓인 양 | **잃지 않았다는 확인** |

## 🔴 트리거 — 이 프로젝트의 구조적 강점

이 사용자는 **앱이 알려줘야 여는 것이 아니다.**

> **손에 실물이 들려 있는 순간 자체가 트리거다.**
> 앱이 만들지 않았지만 **반드시 발생하고**, 그 순간 감정이 가장 높다.
> 시기마다 모양은 다르지만(초음파 사진을 받아 나올 때 / 그림을 내밀 때) **성질이 같다.**

기록 서비스의 최대 난제는 *"사용자가 왜 다시 여는가"*이고, 보통은 앱이 알림으로 그 이유를 만들어야 한다.
**여기서는 그 트리거가 앱 밖에 이미 존재한다.** 알림을 만들 필요가 없다.

**설계에 미치는 영향**: 정해진 주기·마감·창(window) 같은 규칙을 **만들지 않는다.**
손에 뭔가 들어온 날 열면 되고, 아닌 날은 열 이유가 없다. **그것이 정상 상태다.**

> 🔑 **범위를 넓히면서 이 원칙이 깨질 수 있었다.** 임신은 검진 주기가 있어서
> *"다음 검진 알림"* 같은 것을 붙이고 싶어진다. 안 붙였다 —
> 그 주기는 **병원이 만든 것이지 앱이 만든 것이 아니고**, 앱이 그걸 따라 하면
> 트리거가 앱 안으로 들어온다.

## 제품 적합성

| 필요 | 이 서비스가 주는 것 | 남는 마찰 |
|---|---|---|
| 30초 안에 남기기 | 사진 1장 + 말 한 줄 + 날짜. **종류는 묻지 않는다** | 사진 찍는 각도·조명은 우리가 못 도와줌 |
| 말 보존 | 말 입력을 **선택이 아니라 기본 흐름**에 둔다 | 급할 때 건너뛰면 그 말은 못 얻음 → 나중에 덧붙일 수 있게 **편집**이 필요 |
| 그때가 언제였는지 | **임신 주차 · 생후 개월 · 만 나이**로 부른다 | 또래와 비교해주지는 않는다. **일부러 안 한다** |
| 다시 찾기 | 시간순 목록 + 한 해 단위 묶음 + **아이 말로 찾기** | 말이 빈 점은 영원히 안 걸린다. 화면이 그 사실을 말한다 |
| 버려도 된다는 확신 | 등록 직후 문구 + 모아 보기 | — |
| 손에 잡히는 결과 | 책 미리보기 → 주문 | 실제 인쇄는 범위 밖 |

# 부 사용자 — 심사자 🔴

> **실제로 이 화면을 가장 먼저 여는 사람은 부모가 아니라 심사자다.**
> 이전 프로젝트에서 타겟을 "폰 세로"로만 정했다가, 심사자가 노트북으로 열었을 때
> **1483px 화면에 480px 칼럼 하나만 뜨는 실패**가 있었다. 그 재발을 막기 위해 부 사용자로 명시한다.

| | |
|---|---|
| **역할** | 제출된 저장소를 확인하는 개발 담당자 |
| **기기** | 🔴 **노트북 브라우저, 가로. 1440px 안팎. 마우스·키보드** |
| **상황** | `git clone` → `docker compose up` → 브라우저. **쓸 수 있는 시간 5분** |
| **트리거** | 제출된 URL |

## 심사자의 과업

> **5분 안에 "이게 무슨 서비스이고, 만든 사람이 무엇을 왜 그렇게 결정했는지" 판단한다.**

## 심사자의 페인 → 그래서 반드시 만들어야 하는 것

| 페인 | 대응 |
|---|---|
| 켰는데 무슨 서비스인지 모르겠다 | **첫 화면 최상단에 서비스 정의와 타겟을 문장으로.** 버튼보다 위에 |
| 로그인이 막고 있다 | **인증 없음.** 켜면 바로 임신 때부터 초등까지가 보인다 |
| 눌러볼 게 없다 | **모든 작품이 클릭 가능**하고, 등록·주문·상태변경을 직접 해볼 수 있다 |
| 망가뜨릴까 봐 못 누른다 | 🔑 **[데모 초기화]** — 내가 만든 데이터만 지우고 처음 상태로. *망가뜨릴 수 없으면 아무도 안 눌러본다* |
| 화면이 좁아 허전하다 | **반응형.** 폭이 넓어지면 배치가 실제로 달라진다 |
| 왜 이렇게 만들었는지 모르겠다 | 화면 문구 + README + **커밋 로그** |

## 두 사용자가 충돌하는 지점과 해결

| | 부모 | 심사자 | 해결 |
|---|---|---|---|
| 화면 폭 | 폰 세로 | 노트북 가로 | **반응형.** 좁으면 1열, 넓으면 격자. *"넓어지면 칸이 커지는 게 아니라 더 많이 보인다"* |
| 설명 문구 | 이미 아는 서비스라 불필요 | 처음이라 반드시 필요 | 최상단 정의는 **짧게 한 번만.** 사용을 방해하지 않는 위치 |
| 데이터 | 자기 것만 | 남의 것을 봄 | 시드 데이터를 **가상의 아이**로. 실명·얼굴 없음 |
