# 01. 404 — 막다른 길에서 목록으로 돌려보낸다

> 이슈 #1 · `app/not-found.tsx`

## 왜

홈의 클릭 대상 **11개**(등록 CTA 1 + 작품 카드 10)가 전부 404로 떨어지는데,
그 404가 Next.js 기본 화면이라 **홈으로 돌아가는 링크가 없다.**
처음 온 사람이 카드를 누르면 뒤로가기를 아는 사람만 빠져나올 수 있다.

파일 하나로 11개가 한꺼번에 고쳐진다.

## 판단

**갈림길: 전용 스타일 vs 빈 목록과 같은 옷 → 같은 옷(`.blank`)을 골랐다.**
404도 빈 목록도 *"볼 것이 없으니 다음 동작 하나만 남기는 화면"*으로 같은 종류다.
여기서 전용 스타일을 만들면 같은 상황이 두 얼굴로 보인다. 결과적으로 **새 CSS 0줄.**

**갈림길: 문구를 사과로 시작할까 vs 범위를 좁혀줄까 → 범위를 좁히는 쪽.**
일반적인 404는 *"페이지를 찾을 수 없습니다"*면 충분하다. 그런데 이 서비스는
*"실물은 정리하셔도 됩니다"*라고 말하고 받은 기록이다.
부모가 작품 주소를 열었는데 화면이 비면 첫 생각이 *"주소가 틀렸나"*가 아니라
**"내 기록이 날아갔나"**다. 그 불안은 서비스의 약속 자체를 흔든다.
그래서 `남기신 기록은 목록에 그대로 있습니다`를 먼저 둔다.

### 의도적으로 넣지 않은 것

| 안 넣은 것 | 이유 |
|---|---|
| ~~검색창~~ | ~~작품이 10점이다. 목록에서 전부 보이는데 검색을 붙이면 목록이 불충분해 보인다~~ → **뒤집었다.** 홈에 검색이 있다. 근거가 *"점수가 적다"*였는데 그건 **양의 문제**였고, 실제 이유는 양이 아니었다 — **색인을 만드는 사람이 아이여야 한다**는 것이다. 부모가 태그를 다는 대신 아이가 한 말을 그대로 찾는다. 그 판단은 점수와 무관하게 성립한다 |
| "이전 페이지로" 버튼 | 404로 온 경로가 이미 잘못된 경로다. 되돌아가면 같은 자리로 돌아간다. **나가는 문은 하나여야 한다** |
| 삽화·아이콘 | 이 화면의 목적은 위로가 아니라 탈출이다. 시선이 버튼 하나에 가야 한다 |
| 커스텀 `error.tsx` | 404와 500은 사용자가 할 일이 다르다. 같이 묶으면 둘 다 애매해진다. 별건으로 남긴다 |

## AI를 어떻게 다뤘나

**채택**: `.blank` 계열 재사용, 44px 터치 타깃 유지(`globals.css`의 기존 판단과 일치).

**거부·수정 1 — 뷰포트를 실측했다고 쓸 뻔했다.**
창 크기 변경 도구가 `375×812` 요청에 **성공을 반환했다.** 그런데 `window.innerWidth`를 찍어보니
**실제 뷰포트는 500**이었다 — macOS Chrome이 최소 창 너비로 잘라낸 것이다.
성공 반환값만 믿었으면 *"375px에서 확인했다"*는 틀린 문장을 남길 뻔했다.

> 🔑 **도구의 성공 반환값은 결과가 아니라 주장이다.**

같은 origin의 **375px iframe**을 띄워 `matchMedia('(min-width:700px)') === false`까지
확인하는 방식으로 바꿔 실제 375를 측정했다.

**거부·수정 2 — 404 문구의 기본안이 이 서비스와 안 맞았다.**
처음 나온 문구는 *"페이지를 찾을 수 없습니다"*였다. 틀린 말은 아니지만
이 서비스에서 빈 화면이 주는 공포가 *"길을 잃음"*이 아니라 **"기록 소실"**이라는 점을 담지 못한다.
첫 문장을 안심으로 바꿨다.

## 확인

- **1440px** — viewport 실측 1440, 가로 오버플로 없음(`scrollWidth` 1440), `.blank` 1336px 중앙
- **375px** — viewport 실측 375(iframe), `(min-width:700px)` false, 오버플로 없음, `.blank` 343px
- 버튼 높이 **44px** (폰 한 손 조작 기준)
- HTTP 상태 **404** (200으로 응답하지 않는다)
- 실제 클릭 왕복: `/artwork/does-not-exist` → 클릭 → `/` 에서 카드 10개·"작품 10점"
- `npm run lint` 통과
