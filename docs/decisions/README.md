# 판단 기록

각 화면을 만들 때 **무엇을 두고 갈렸고, 왜 그쪽을 골랐고, 무엇을 일부러 넣지 않았는지**를 화면 하나에 파일 하나로 남긴다.
`git log`는 *무엇을 했는지*를 말하고, 여기는 *왜 그렇게 했는지*와 **왜 다른 쪽을 버렸는지**를 말한다.

| 파일 | 화면 |
|---|---|
| [`01-not-found.md`](./01-not-found.md) | 404 |
| [`02-artwork-detail.md`](./02-artwork-detail.md) | 작품 상세 |
| [`03-artwork-new.md`](./03-artwork-new.md) | 작품 등록 |
| [`04-artwork-edit.md`](./04-artwork-edit.md) | 설명 편집 |
| [`05-readme.md`](./05-readme.md) | README · 클린 클론 검증 |

각 문서의 구성은 같다.

| 절 | 내용 |
|---|---|
| **왜** | 이 화면이 없으면 사용자가 무엇을 못 하나 |
| **판단** | 갈림길과 고른 이유 · **의도적으로 넣지 않은 것** |
| **AI를 어떻게 다뤘나** | 채택한 것과 **거부·수정한 것** — 무엇이 틀렸고 어떻게 발견했나 |
| **확인** | 실측값. 잰 값만 적는다 |

## 🔴 이 문서들이 저장소 안에 있는 이유

처음에는 **GitHub PR 본문**에 적었다(PR #5~#9). 그런데 공개 전에 히스토리에서 지워야 할 것이
남아 있어 저장소를 지우고 다시 만들었고, **그때 이슈와 PR이 같이 사라졌다.**

**저장소를 지우면 이슈·PR도 지워진다** — 재생성을 결정할 때 이걸 계산에 넣지 않았다.
커밋 메시지에 남은 `(#5)`~`(#9)`는 그때 사라진 PR을 가리킨다.

본문은 되살렸고, 되살리면서 **PR보다 저장소 안이 맞는 자리**라고 판단했다.

- `clone`만 하면 보인다. GitHub에 들어가 머지된 PR을 뒤질 필요가 없다
- 저장소를 다시 만들어도 안 사라진다. **같은 사고를 두 번 당하지 않는다**
- 코드와 같은 커밋 이력을 탄다 — 판단이 바뀌면 그 변경도 diff로 남는다
