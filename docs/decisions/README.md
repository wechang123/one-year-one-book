# 판단 기록

각 화면을 만들 때 **무엇을 두고 갈렸고, 왜 그쪽을 골랐고, 무엇을 일부러 넣지 않았는지**를 화면 하나에 파일 하나로 남긴다.
`git log`는 *무엇을 했는지*를 말하고, 여기는 *왜 그렇게 했는지*와 **왜 다른 쪽을 버렸는지**를 말한다.

| 파일 | 무엇에 대한 판단인가 | 레벨 |
|---|---|---|
| [`01-not-found.md`](./01-not-found.md) | 404 | Lv1 |
| [`02-artwork-detail.md`](./02-artwork-detail.md) | 작품 상세 | Lv1 |
| [`03-artwork-new.md`](./03-artwork-new.md) | 작품 등록 | Lv1 |

각 문서의 구성은 같다.

| 절 | 내용 |
|---|---|
| **왜** | 이 화면이 없으면 사용자가 무엇을 못 하나 |
| **판단** | 갈림길과 고른 이유 · **의도적으로 넣지 않은 것** |
| **AI를 어떻게 다뤘나** | 채택한 것과 **거부·수정한 것** — 무엇이 틀렸고 어떻게 발견했나 |
| **확인** | 실측값. 잰 값만 적는다 |

## 🔴 이 문서들이 저장소 안에 있는 이유

처음에는 **GitHub PR 본문**에 적었다(PR #5~#9). 그런데 공개 전에 히스토리에서 지워야 할 것이
남아 있어 저장소를 지우고 다시 만들었고, **그때 이슈와 PR이 같이 사라졌다.**

**저장소를 지우면 이슈·PR도 지워진다** — 재생성을 결정할 때 이걸 계산에 넣지 않았다.
커밋 메시지에 남은 `(#5)`~`(#9)`는 그때 사라진 PR을 가리킨다.

본문은 되살렸고, 되살리면서 **PR보다 저장소 안이 맞는 자리**라고 판단했다.

- `clone`만 하면 보인다. GitHub에 들어가 머지된 PR을 뒤질 필요가 없다
- 저장소를 다시 만들어도 안 사라진다. **같은 사고를 두 번 당하지 않는다**
- 코드와 같은 커밋 이력을 탄다 — 판단이 바뀌면 그 변경도 diff로 남는다

### ⚠️ 위 문단을 처음 쓸 때 틀린 게 하나 있었다

*"커밋 메시지에 남은 `(#5)`~`(#9)`는 그때 사라진 PR을 가리킨다"*고 적었는데,
**확인하지 않고 기억으로 쓴 문장**이었다.

실제로는 그 직후에 **번호가 재사용되면서 더 나빠졌다** — 새 PR이 `#5`를 받아서
`feat: 404 화면 …(#5)`가 **엉뚱한 PR을 가리키게** 됐다. 죽은 링크보다 나쁘다.

그래서 옛 참조 다섯 개를 커밋 메시지에서 **지웠다.**
이번에는 저장소를 다시 만들지 않았다 — **옛 커밋에 지워야 할 내용이 없어서
SHA로 남아도 무해했고, 그러면 force push로 충분하다.** 덕분에 이슈와 PR이 살아남았다.

> 🔑 **앞선 두 번은 "비밀을 지우는 것"이라 삭제·재생성이 필요했고, 이번은 "표기를 고치는 것"이라 아니었다.**
> 같은 목적(*히스토리를 고친다*)이라도 **무엇을 지우려는지에 따라 필요한 도구가 다르다.**
> 두 번째 삭제 때 이 구분을 못 해서 이슈·PR을 날렸다.

**현재 커밋 메시지의 `(#N)`은 실재하는 PR을 가리킨다.**
번호를 여기 적지 않는다 — 이 문단이 *"확인하지 않고 기억으로 썼다"*를 고백하는 자리인데
**범위를 박아두면 다음 PR이 머지되는 순간 다시 틀린다.** 실제로 한 번 그렇게 늙었다.
PR 목록은 [GitHub](https://github.com/wechang123/one-year-one-book/pulls?q=is%3Apr)에서 볼 수 있다.
