# 05. README · 클린 클론 검증

> `README.md` · `docs/worklog.md`

## 왜

저장소에 **README가 없었다.** 처음 여는 사람이 `clone` 후에 무엇을 해야 하는지 알 방법이 없었다.

## 판단

**README에는 실제로 확인한 값만 적었다.**
`git clone git@github.com:…`으로 **GitHub URL에서** 받아 **빈 볼륨**으로 기동한 결과다.
(이전 검증은 `origin`이 로컬 경로였다 — 제출물을 검증한 게 아니었다.)

**`docker-compose.yml`의 `name:`이 고정이라 볼륨 이름도 고정된다.**
그대로 `up` 하면 **마이그레이션·시드가 이미 끝난 기존 볼륨을 재사용**해서 클린 검증이 안 된다.
저장소를 처음 여는 사람의 PC에는 그 볼륨이 없으므로, 별도 프로젝트 이름으로 빈 볼륨을 만들어
처음부터 돌렸다.

**포트 변수의 근거를 문서가 아니라 사건으로 적었다.**
검증 중에도 5433은 다른 프로세스가 잡고 있었다. 그걸 내리는 대신 이쪽이 비켜갔다.
*"남이 쓰는 포트를 뺏는 대신 이쪽이 옮길 수 있어야 한다"* — 이게 변수를 뺀 이유고,
README에 그 사건 그대로 썼다.

**시드 출처 표 10칸을 채웠다.** `06-house.jpg`의 출처를 특정하기 전까지는
*"한 장이라도 못 대면 표를 쓰지 않는다"*는 원칙 때문에 **표 전체가 막혀 있었다.**
CC0/PD는 표기 의무가 없지만 의무가 없어도 밝히는 것이 맞다고 봤다.

**커밋 메시지를 고치는 대신 worklog에 남겼다.**
목록 화면 커밋에 *"1440px에서 4열(카드 322px)임을 실측했다"*고 썼는데 실제 측정 뷰포트는 1512px이었다.
진짜 1440에서 다시 재니 **4열·322px로 같았다**(`.page`의 `max-width`가 1400px이라
그 이상에서는 배치가 동일하다). **숫자는 맞고 출처가 틀린 문장**이었다.

> 🔑 맞는 숫자를 고치자고 push된 히스토리를 force로 흔들 이유가 없다고 봤고,
> **정정을 정정으로 남기는 편이 틀렸던 적이 없는 것처럼 만드는 것보다 낫다**고 판단했다.

## AI를 어떻게 다뤘나

**거부·수정 1 — 오염 검사에서 내가 방금 쓴 문서가 걸렸다.**
히스토리에서 제3자 실명을 지운 경위를 worklog에 적으면서 **그 실명을 본문에 그대로 다시 썼다.**
커밋 직전 전수 grep이 잡아냈다. *"무엇을 지웠는지"*를 설명하려면 그것을 쓰지 않고 설명해야 한다.
→ 단어 대신 **현상**으로 서술하도록 고쳤다.

**거부·수정 2 — 검사 스크립트 자체가 파일 하나를 건너뛰고 있었다.**
`git ls-files | while read f; do grep … "$f"; done`으로 추적 파일을 훑었는데,
git이 **한글 파일명을 이스케이프해서** 출력하기 때문에 `docs/04b-대안-생성이미지(채택안함).md`가
grep에 도달하지 못했다. *"0건"*이 **"깨끗하다"가 아니라 "안 봤다"**였던 것이다.
알아챈 계기는 **알려진 1건이 결과에 안 나온 것**이었다 — 04b에 있는 걸 아는 문자열이 안 걸렸다.
`git grep`으로 바꾼 뒤 정상적으로 잡혔다.

> 🔑 검사 결과가 0일 때, **검사가 동작했다는 증거**가 따로 필요하다.
> 나오는 게 없는 것과 보지 않은 것은 같은 모양이다.
