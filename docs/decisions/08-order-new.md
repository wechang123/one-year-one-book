# 08. 주문 넣기 — 사고와 의도를 가르는 중복 차단

> 이슈 #7 · PR #14 · `app/book/[year]/order/` · `lib/order-no.ts` · `lib/phone.ts`

## 왜

책을 만들어도 **주문할 수 없었다.** 결제·배송 연동은 범위 밖이지만
*"주문을 기록하고 흐름을 관리하는 것"*까지는 이 서비스가 성립하는 데 필요하다.

## 판단

### 주문번호 — 전화로 부를 수 있어야 한다

`Order.id`는 cuid다. 그건 기계가 쓰는 값이고 **"주문번호가 어떻게 되세요"에 답할 수 있는 값이 아니다.**

형태를 `20260803-7K2M`로 정했고, 세 가지가 형태를 결정했다.

| 결정 | 이유 |
|---|---|
| 날짜가 앞 | 언제 넣은 주문인지 **번호만 보고 안다** |
| 뒤는 네 글자 | 더 길면 **불러주다 틀린다** |
| `0 O 1 I L` 제외 · 대문자만 | 전화로 부를 때 **되묻게 되는 글자**다 |

날짜는 **반드시 `lib/now.ts`를 거친다** — 직접 만들면 자정을 걸칠 때 번호와 `createdAt`이 하루 어긋난다.
무작위는 `Math.random`이 아니라 `crypto`다 — **주문번호는 남의 주문을 넘겨다볼 수 있는 값이면 안 된다.**

**겹치면 다시 뽑되, 미리 조회해서 피하지 않는다.**
조회와 생성 사이가 비어 있어 그 사이에 다른 요청이 같은 값을 쓸 수 있다.
**DB의 `@unique`가 최종 방어선**이고, 코드는 그 결과를 받아 다시 시도할 뿐이다.

### 중복 클릭 — 버튼과 서버가 하는 일이 다르다

| | 무엇을 막나 | 그것만으로 부족한 이유 |
|---|---|---|
| **버튼 잠금** | **두 번 누르는 일 자체**를 줄인다 | 서버 액션은 **폼을 거치지 않고도** 호출된다 |
| **서버 검사** | **두 건이 생기는 것**을 막는다. 새로고침·뒤로가기 재전송까지 | 사용자에게 아무 응답이 없다 |

**60초 창을 쓴 이유는 사고와 의도를 가르기 위해서다.**
재전송은 **몇 초 안에** 일어나고, *"할머니 드릴 한 권 더"*는 그 자리에서 연달아 넣는 일이 아니다.
중복이면 오류를 내지 않고 **이미 만들어진 주문으로 보낸다.**

### 책 한 권에 주문 여러 건

`Collection`은 `@@unique([profileId, year])`로 한 권, `Order`는 **unique가 없다.**
이 층위 차이가 화면에 드러나야 한다 — 받는 분 칸에 *"선물이면 받으실 분 이름으로"*.

### 연락처 검증을 자릿수만 본다

이 값의 쓸모는 **"문제가 생겼을 때 연락이 닿는 것"** 하나다.
형식을 촘촘히 잡을수록 070·안심번호 같은 **진짜 번호가 거절당하고,
거절당한 사람은 형식을 맞추려고 가짜를 넣는다.** 그러면 검증은 통과하는데 **연락은 안 닿는다.**
**검증이 목적을 배신하는 경우**라, 숫자 개수(9~11)만 본다.

### 의도적으로 넣지 않은 것

| 안 넣은 것 | 이유 |
|---|---|
| 가격·쪽수·배송예정일 | 제작 사양이 없다 |
| 결제 | 범위 밖. 그리고 **없다는 사실을 화면이 말한다** — 결제 칸이 없는 걸 *"아직 안 만든 것"*으로 읽으면 주문 넣고 기다리게 된다 |
| 주소 검색 API | 외부 API 호출 금지가 이 저장소의 규칙이다 |
| 주문 수정·취소 | 상태가 전진하는 값이라 수정은 *"어느 시점의 주소로 보내나"*를 만든다. 그 답을 설명할 수 없다 |

## AI를 어떻게 다뤘나

**🔴 거부·수정 1 — 제출해보고서야 입력이 사라지는 걸 발견했다.**
이름·주소를 넣고 연락처만 틀리게 제출했더니 오류가 뜨면서 **세 칸이 전부 비었다.**
React 19는 폼 액션이 끝나면 입력칸을 초기화한다 — 성공 뒤에는 맞지만
**오류로 되돌아왔을 때는 주소까지 다시 치게 만든다.**
**같은 결함이 이미 머지된 작품 등록·편집 폼에도 있어서 같이 고쳤다**([03](./03-artwork-new.md) 참조).

**거부·수정 2 — 제출 중 상태를 "확인했다"고 쓸 뻔했다.**
폴링 간격(25ms)보다 액션이 빨라 표본을 못 잡았고, 더 촘촘히 돌렸더니 **렌더러가 멈췄다.**
`MutationObserver`로 바꿔 `"주문을 넣는 중…" disabled=true`를 **실제로 관찰**하고 적었다.

**거부·수정 3 — 중복 차단을 "버튼 잠금으로 충분"하다고 넘어갈 뻔했다.**
그건 [03](./03-artwork-new.md)에서 `accept` 속성을 방어라고 부를 뻔한 것과 **정확히 같은 형태**다.
