# 02. 작품 상세 — 사진 한 장이 원본을 대신하게

> 이슈 #2 · `app/artwork/[id]/page.tsx`

## 왜

목록의 카드 10개가 `/artwork/[id]`를 가리키는데 그 화면이 없었다.
목록에서는 아이 말이 **세 줄에서 잘리고**(`.quote`의 line-clamp) 사진은 카드 크기에 갇힌다.

이 서비스는 부모에게 *"실물은 정리하셔도 됩니다"*라고 말하려고 만들었다.
그 말이 성립하려면 화면 속 한 장이 서랍 속 원본을 대신할 만큼 보여야 한다.
**그걸 뒷받침하는 화면이 없는 상태였다.**

## 판단

**갈림길: 사진 비율 고정 vs 원본 비율 → 원본 비율.**
목록의 `.card__frame`은 `aspect-ratio: 4/3`으로 고정한다(카드 높이를 고르게 하려고).
상세에서 같은 짓을 하면 안 된다 — 시드 10장의 실측 비율이
**1280×905(가로)부터 1194×1843(세로)까지** 제각각이고, 실제 아이 그림이 원래 그렇다.
비율을 고정하면 잘리거나 여백이 생긴다. 잘린 자리에 아이가 설명한 것이 있을 수 있다.

**갈림길: 사진을 화면 폭에 꽉 채울까 → 높이 72%로 제한.**
세로로 긴 그림(1194×1843)을 폭에 맞추면 화면을 넘어간다.
**한 장을 보는 데 스크롤이 필요해지면 "원본 대신 보기"가 성립하지 않는다.**
`max-height: 72vh` + 원본 비율 유지로 어떤 비율이 와도 한 화면에 들어온다.

**갈림길: 900px에서 무엇을 할까 → 아이 말을 사진 옆으로 올린다.**
목록의 반응형 원칙은 *"넓어지면 칸이 커지는 게 아니라 더 많이 보인다"*인데
상세에는 늘릴 칸이 없다. 대신 좁을 때 사진 **아래** 있던 말이 넓어지면 **옆**으로 온다.
그림과 말은 따로 보면 반쪽이라, 스크롤 없이 같이 보이는 것이 이 화면의 이득이다.
(경계가 목록의 700px과 다른 것은 여기 놓이는 물건이 다르기 때문이다 —
사진이 260px짜리 글 칸을 떼어주고도 원본을 대신할 만큼 남아야 한다)

**원본보다 크게 늘리지 않는다.** `seed-09-tadpole`은 원본이 359×606이라
1440px에서도 361×608로 보인다. 넓은 칸을 채우려고 늘리면 흐려진다.
**작아 보이는 것보다 흐린 것이 원본을 더 못 대신한다.**

**없는 id에 전용 화면을 만들지 않고 `notFound()`로 넘겼다.**
주소를 잘못 친 것과 지워진 작품을 사용자는 구분할 수 없고, **할 일도 같다** — 목록으로 돌아가는 것.
[01](./01-not-found.md)에서 만든 `app/not-found.tsx`가 그대로 받는다.

### 의도적으로 넣지 않은 것

| 안 넣은 것 | 이유 |
|---|---|
| 라이트박스·확대 | `72vh`로 이미 한 화면에 다 들어온다. 확대가 필요하다는 건 기본 크기가 틀렸다는 뜻이라, 확대를 붙이면 그 잘못을 덮게 된다 |
| 이전/다음 작품 이동 | 목록이 한 화면에 10점을 다 보여준다. 목록을 거치는 게 한 번 더 누르는 대신 **어디쯤인지**를 알려준다 |
| 삭제 버튼 | 이 서비스는 남기려고 등록한다. 되돌릴 수 없는 버튼을 상세에 두면 [데모 초기화]와 역할이 겹치고 성격이 다르다 |
| 편집 진입 링크 | 편집 화면이 아직 없었다. **없는 화면으로 가는 링크를 먼저 만들지 않는다** — [04](./04-artwork-edit.md)에서 화면과 진입점을 같이 넣었다 |
| `generateMetadata` | 탭 제목에 아이 말을 넣는 건 되지만 지금 필요한 근거가 없다 |

## AI를 어떻게 다뤘나

**채택**: 목록에서 검증된 `getPrisma` + `select` 패턴. 여기서도 **사진 바이트를 읽지 않는다**
(`width`/`height`만 select). 바이트는 `/api/photo/[id]`가 따로 내려준다.

**거부·수정 1 — `aspect-ratio`를 상세에도 쓸 뻔했다.**
목록 카드에서 검증된 패턴이라 그대로 가져오려 했다. 쓰기 전에 DB를 조회해보니
10장의 비율이 `1.69 ~ 0.58`로 흩어져 있었다. **한 값으로 묶으면 전부 잘리거나 여백이 생긴다.**

> 🔑 *"검증된 패턴을 복사한다"*가 항상 옳은 게 아니라 **같은 물건일 때만** 옳다.

**거부·수정 2 — `alt`에 아이 말을 넣자는 기본안을 거부했다.**
접근성 관행으로는 맞아 보이지만, 아이 말은 그림의 설명이 아니라 **그림을 보고 한 말**이고
바로 아래에 글로 나와 있다. 넣으면 스크린리더가 같은 문장을 두 번 읽는다.

**거부·수정 3 — "빈 상태를 확인했다"고 쓸 뻔했다.**
시드 10점은 **전부 아이 말이 있어서** 빈 분기가 한 번도 렌더된 적이 없었다.
코드를 읽고 *"되겠지"*로 넘어갈 뻔했고, 대신 DB에서 한 건을 `NULL`로 만들어 실제로 렌더시킨 뒤
원문으로 되돌리고 `lib/seed-data.ts`와 문자열 대조해 복구를 확인했다.

## 확인

실측값 (`window.innerWidth`를 직접 찍은 값. 창 크기 변경 도구의 성공 반환값은 믿지 않는다 —
[01](./01-not-found.md)에서 375 요청에 500이 나왔다)

| | 1440px | 375px |
|---|---|---|
| 2단 배치 | ✅ 사진 옆에 말 | ❌ 1단, 말이 사진 아래 (의도대로) |
| 가로 오버플로 | 없음 | 없음 |
| 가로 그림 `1280×741` | 952×552 | 343×199 |
| 세로 그림 `1194×1843` | — | 328×505 |
| 원본 비율 유지 | ✅ | ✅ |

- **72vh 상한 작동** — 375×600에서 세로 그림이 정확히 **432px**(=600의 72%)로 잘리고 비율 유지
- **빈 상태** — 아이 말 `NULL`일 때 "아직 안 물어봤어요" 분기 렌더 확인 후 데이터 복구
- **없는 id** → HTTP 404, `app/not-found.tsx` 렌더
- 돌아가기 버튼 44px
- 데이터 무결성 — 작품 10점 · `childQuote IS NULL` 0건 · 사진 바이트 **1719 kB** 유지
- `npm run lint` 통과
