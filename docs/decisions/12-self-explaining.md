# 13. 자기설명 UI — 실제 이미지가 없어도 무엇을 하는 곳인지 알게

> 이슈 #48 · `app/artwork/new/form.tsx` · `app/page.tsx` · `app/globals.css`

## 왜

시드 이미지는 소품이다. 판정 대상은 **인터페이스가 스스로를 설명하는가**이고,
그 기준은 하나다 — *"사용자가 다음에 뭘 할지 아는가."*

그래서 먼저 **판정부터 했다.** 고칠 곳을 정하기 전에 지금 화면이 실제로 무슨 말을 하는지 봤다.

---

## 1. 업로드 자리 — 판정: **아무 말도 안 했다**

고르기 전에 그 자리에 있던 것 전부:

```
사진 [필수]
[ 파일 선택 ]
JPG · PNG · WebP, 8MB까지. 벽에 붙은 채로 찍어도 됩니다.
```

**무엇을 받는 곳인지도, 올리면 어떻게 보일지도 말하지 않는다.**
형식과 크기는 **제약이지 설명이 아니다.** 그리고 빈 DB로 처음 여는 사람에게는
이 화면이 서비스를 설명하는 유일한 자리인데 비어 있었다.

**갈림길: 문구만 / 크기 안내만 / 종횡비 틀 + 문구 → 셋째.**

- 문구만 두면 *"어떻게 보일지"*는 여전히 안 보인다
- 크기 안내는 이미 아래에 있다
- **자리를 실제로 그려두면**, 고른 뒤 **같은 자리에 미리보기가 들어서면서** 방금 읽은 말이 그 자리에서 증명된다

실제 문구:

> ### 여기에 사진이 들어갑니다
> 그림 · 만들기 · 상장 · 초음파 사진 — **손에 들려 있는 것이면 됩니다**
> 원본 비율 그대로 보입니다. 잘리지 않아요.

**틀은 정사각이다 — 목록 카드와 같은 비율.**
여기서 본 자리가 목록에서도 같은 모양이라야 *"이렇게 보이는구나"*가 맞는 말이 된다.

**틀이 `<label for="photo">`라 눌러도 파일 선택이 열린다.** 아래 입력칸은 그대로 뒀다 —
틀은 설명이고, 입력칸은 **키보드와 JS 없는 경로에서도 동작해야 하는 진짜 컨트롤**이다.

> 🔑 여기서 **종류를 묻지 않는다는 판단이 문구로 성립한다.**
> 그림·상장·초음파를 드롭다운으로 받으면 등록이 무거워지는데,
> 범위는 **한 줄로 말하면 되는 것**이었다. 고르게 하지 않고 알려주면 끝난다.

## 2. 빈 상태 전수 — 여섯 개

| 빈 상태 | 지금 문구 | 다음 행동을 말하나 |
|---|---|---|
| 남긴 것 0점 (`/`) | `아직 남긴 것이 없어요.` + 무엇을 왜 받는지 | ✅ [첫 한 점 남기기] |
| 검색 0건 (`/?q=…`) | `"바다"가 들어간 말이 없어요.` + **말이 빈 N점은 안 걸린다** | ✅ [전체 보기] |
| 책 0권 (홈 책 줄) | `2026년 · 진행 중 · 지금까지 N점` | ✅ [책으로 묶기] |
| 주문 0건 (`/orders`) | `아직 넣으신 주문이 없어요.` | ✅ [책 묶으러 가기] |
| 그 해 0점 (`/book/[year]`) | `2026년에 남긴 것이 아직 없어요.` | ✅ [한 점 남기기] |
| 되짚어볼 것 0점 (`/recall`) | `아직 되짚어볼 것이 없어요.` | ✅ [첫 한 점 남기기] |

**문구 자체는 여섯 개 다 통과했다. 그런데 그 위가 틀렸다.**

### 🔴 남긴 것이 0점인데 검색 칸이 떠 있었다

빈 화면 위에 `아이가 한 말로 찾기` 입력칸과 [찾기] 버튼이 그대로 있었다.
**찾을 것이 하나도 없는데 찾는 칸이 있는 것**이고,
그러면 처음 온 사람이 봐야 할 것 — *"다음에 뭘 눌러야 하는지"* — 가
입력칸과 버튼 사이에서 흐려진다.

빈 화면은 **안내할 자리가 가장 넓은 화면**이다. 그 자리를 검색에 내주지 않는다.

```
고치기 전 · 빈 홈 · 검색 폼 있음: True
고친 뒤   · 빈 홈 · 검색 폼 있음: False
```

## 3. CTA 사슬

| 화면 | 주 행동 | 그다음 |
|---|---|---|
| `/` | **[사진 등록]** | 등록 화면 |
| `/artwork/new` | [저장하기] | 방금 남긴 한 점 |
| `/artwork/[id]?saved=1` | (말이 비었으면) [저장하기] | **없음 — 아래 참조** |
| `/artwork/[id]` | [설명 고치기] · 앞뒤 병치 | 편집 / 이웃 한 점 |
| `/` 책 줄 | [책으로 묶기] | `/book/[year]` |
| `/book/[year]` | [주문하기] | 주문 폼 |
| `/book/[year]/order` | [주문 넣기] | 책 + 주문번호 |
| `/orders` | 주문 한 건 고르기 | `/orders/[orderNo]` |
| `/orders/[orderNo]` | [인쇄 시작] → [배송 시작] | 같은 화면, 상태 전진 |
| `/recall` | [한 장씩 보기] | `/recall/[id]` → … → `/recall/done` |
| `/child` | [저장하기] | `/` (축이 바뀐 목록) |

### 🔴 경쟁하던 지점 — 홈에 진한 버튼이 셋이었다

`[사진 등록]` · `[찾기]` · `[책으로 묶기]`가 **같은 무게**였다.
처음 온 사람의 눈은 그중 무엇을 눌러야 할지 고르는 데 시간을 쓴다.

**[찾기]를 `btn--ghost`로 내렸다.**
검색은 **이미 있는 것을 좁히는 행동**이라 새로 만드는 행동과 무게가 같으면 안 된다.

**[책으로 묶기]는 그대로 뒀다.** 테두리로 분리된 구역 안의 주 행동이고,
그 구역은 화면 아래쪽에 따로 있다. 그리고 시드가 책·주문을 0건으로 비워둔 것이
**직접 눌러보라는 배치**라, 여기를 흐리면 그 배치가 무의미해진다.

```
고치기 전 홈 진한 버튼: ['사진 등록', '찾기', '책으로 묶기']
고친 뒤   홈 진한 버튼: ['사진 등록', '책으로 묶기']
```

### 등록 직후 화면에는 **다음 CTA를 안 붙인다**

사슬이 거기서 한 번 끊긴다. 의도한 것이다.
그 화면의 결론은 *"이제 정리하셔도 됩니다"* — **허락**이고,
거기에 [책으로 묶기]를 붙이면 **허락이 판매로 가는 통로**가 된다.
`/recall/done`에서 같은 이유로 이미 거절한 판단이다(`app/recall/done/page.tsx` 머리말).
대신 **목록으로 돌아가는 길이 항상 화면 맨 위에 있다.**

## 4. 종횡비가 섞이는 격자 — 틀을 4:3에서 1:1로

세로 A4 상장과 가로 8절 그림이 같은 격자에 들어온다.
**자르지 않기로 이미 정했으므로**(`object-fit: contain` — 잘린 자리에 아이가 설명한 것이 있을 수 있다)
남는 문제는 **여백**이고, 여백은 틀 비율이 정한다.

| 틀 | 들어오는 것 | 쓰는 면적 | 여백 |
|---|---|---|---|
| **4:3** | A4 세로 (1:1.41) | 폭의 **53%** | 좌우 47% |
| **1:1** | A4 세로 | 폭의 **71%** | 좌우 29% |
| **1:1** | 8절 가로 (4:3) | 높이의 **75%** | 위아래 25% |

`4/3`은 **가로 그림만 들어오던 시절의 값**이다.
정사각은 어느 쪽에도 유리하지 않은 대신 **어느 쪽도 크게 손해 보지 않는다.**

**대가**: 카드가 조금 높아져 한 화면에 덜 들어온다. 받아들였다 —
격자는 색인이고, **절반이 여백인 칸은 색인 구실을 못 한다.**

### 화면이 종류를 구분해 보여줘야 하는가 → **아니다**

구분할 값이 없다(종류를 안 받는다). 그리고 **구분할 필요도 없다** —
격자에서 필요한 것은 *"어느 것이 그것인지"*이고, 그건 사진이 말한다.
`상장`이라는 이름표는 사진에 이미 적혀 있다.
