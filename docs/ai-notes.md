# AI 도구 사용 기록 — 전체

README의 "AI 도구 사용 내역"이 요약이고, 이 문서가 전체 기록입니다.
각 항목의 발생 시각과 전말은 [`worklog.md`](./worklog.md)와 [`decisions/`](./decisions/)에 있습니다.

## 어떻게 썼나

이 저장소는 AI 에이전트(Claude Code)와 페어로 만들었습니다. 에이전트에게 준 작업 규칙이
[`CLAUDE.md`](../CLAUDE.md)이고, 그중 첫 번째가 "이해하지 못한 코드는 채택하지 않는다"입니다.
그래서 커밋이 논리 단위로 쪼개져 있고, 각 커밋 본문에 왜 그렇게 했는지가 적혀 있습니다.

| 도구 | 어디에 | 어떻게 |
|---|---|---|
| Claude Code | 코드·문서 전반 | 페어 프로그래밍. 화면·스키마·검증을 같이 짜고, 채택 전에 근거를 설명하게 함 |
| Claude Code | 시드 문장 10개 | 그림을 한 장씩 실제로 열어 보고 그 그림에 맞는 말을 씀 |
| Claude Code | 타당성 조사 | 경쟁 서비스·라이선스 조사. 출처를 확인할 수 없는 수치는 버림 |
| Claude Code | 시드 이미지 12장 | 저장소 안의 코드(`scripts/seed-images.mjs`)가 그림. 이미지 모델을 쓰지 않은 이유는 재현성 — [04b](./04b-%EC%83%9D%EC%84%B1%EC%9D%B4%EB%AF%B8%EC%A7%80.md) |

## AI가 틀렸고 내가 잡은 것 — 전체 목록

공통점은 "코드는 도는데 확인이 틀렸다"입니다. AI가 짠 코드를 읽고 이해하는 것보다,
내가 한 확인이 진짜 확인인지 되묻는 일이 더 자주 필요했습니다.

| 무엇이 틀렸나 | 어떻게 발견했나 |
|---|---|
| Prisma 7은 스키마에 `url`을 둘 수 없다 | AI가 어제 같은 문제를 겪고 커밋 메시지에 적어뒀는데, 새 저장소에서 그 기록을 참조하지 않고 관성대로 썼다. Docker 빌드가 `P1012`로 죽어 컨테이너 로그로 찾았다. 검증된 설정은 다시 쓰지 말고 복사한다 |
| 크기 검사가 도달할 수 없는 코드였다 | `bodySizeLimit`과 앱 한도가 둘 다 8MiB였는데, 앞의 것은 파일이 아니라 요청 본문 전체에 걸린다. 8.5MB 파일을 실제로 만들어 재현했고, 설정을 되돌려 한국어 안내가 0건 뜨는 것까지 확인했다 |
| [다시 시도] 버튼이 복구를 못 했다 | `error.tsx`의 표준 형태(`onClick={reset}`)를 넣고 눌러봤더니 DB를 껐다 켠 뒤에도 오류 화면이 남았다. 서버 컴포넌트 쿼리 실패라 `router.refresh()`가 필요했다 |
| 오류가 나면 사용자가 친 값이 전부 사라졌다 | 연락처만 틀리게 제출했더니 세 칸이 전부 비었다. React 19가 폼 액션 후 입력칸을 초기화한다. 이미 머지된 폼들에도 같은 결함이 있어 같이 고쳤다 |
| `accept` 속성을 "방어"라고 부를 뻔했다 | 그건 갤러리에서 보이는 걸 줄이는 안내일 뿐이다. 내용이 텍스트인데 `type`만 이미지라고 주장하는 파일을 실제로 밀어넣어 뚫었다 |
| 뷰포트를 "실측했다"고 쓸 뻔했다 (2번) | 창 크기 변경 도구가 375×812에 성공을 반환했는데 실제 뷰포트는 500이었다(OS 최소 창 너비). 도구의 성공 반환값은 결과가 아니라 주장이다 |
| 오염 검사에 방금 쓴 문서가 걸렸다 | 히스토리에서 제3자 실명을 지운 경위를 적으면서 그 실명을 본문에 다시 썼다. 커밋 직전 전수 검사가 잡았다 |
| 검사 스크립트가 파일 하나를 건너뛰고 있었다 | `git ls-files`가 한글 파일명을 이스케이프해 출력해서 `grep`에 도달하지 못했다. 결과가 0일 때는 검사가 동작했다는 증거가 따로 필요하다 |
| 같은 판정을 두 곳에서 따로 정의했다 | 중복 주문 차단의 조회는 이름·연락처·주소를 보고 유니크 키는 연락처만 봤다. 받는 사람이 달라도 연락처가 같으면 둘째 주문이 조용히 사라졌다 |
| [처음 상태로 되돌리기]가 새 열을 안 되돌렸다 | `quoteBy`를 화면까지 연결하고 시드에만 안 넣었다. 되돌릴 수 있는 열을 늘릴 때마다 시드도 같이 늘어나야 한다 |
| 빈 상태는 코드를 읽어서 판정할 수 없었다 | 테이블을 비우고 실제로 열어보니, 찾을 것이 없는데 검색 입력칸이 빈 화면 위에 떠 있었다. 문구는 다 맞았고 틀린 것은 그 위였다 |
| 주석이 정사각이라고 말하는데 화면은 1.78이었다 | 등록 화면 사진 자리를 "목록 카드와 같은 비율"이라 적어놓고 `max-height`로 높이를 잘랐다. 375px에서만 정사각이었다 |
| 같은 값을 두 번 재고 다르게 나왔는데 아무 데도 안 적었다 | 375px 카드 폭이 328(게이트)과 343(문서)으로 달랐다. 원인은 스크롤바 15px. 두 값이 다르면 그것 자체가 적을 값이다 |
| 조건이 바뀌었는데 예외를 그대로 뒀다 | "진한 버튼은 하나"의 예외를 [책으로 묶기]에 줬는데, 시드가 넓어져 연도가 넷이 되자 진한 버튼이 다섯이 됐다 |
| 아이콘 두 개가 코드로는 멀쩡하고 화면에서만 틀렸다 | 따옴표 아이콘이 14px에서 `))`로 읽혔고, `<summary>`에 `display: flex`를 걸자 펼침 삼각형이 사라졌다. 둘 다 타입 검사와 빌드를 통과한다. 렌더해야 보인다 |
| 강조색 토큰이 본문 색을 들고 있었다 | `--accent`가 `--ink`와 같은 값이었다. "밋밋하다"는 인상을 색깔별 글자 수(먹 498 / 회색 463 / 종이색 5)로 바꿔 재고 나서야 고칠 것이 정해졌다 |
| 자기 CSS에 적어둔 원칙을 자기가 어기고 있었다 | "넓어지면 더 많이 보인다"를 격자만 지켰다. 검색 입력칸은 1440px에서 1263px까지 늘어났다 — 찾는 말은 두 글자다 |
| "얼마를 아꼈나"만 재고 "무엇이 그 값을 만들었나"는 안 쟀다 | 검색 폼을 접어 102px을 아꼈다고 봤는데, 쪼개보니 토글이 실제로 산 것은 8px이었다. 합계만 보면 어떤 해법이든 좋아 보인다 |
| 한국어 화면에서 `ch`를 단위로 썼다 | `64ch`는 64자가 아니라 한글 약 34자다. `ch`는 숫자 0 한 글자의 폭이다. 렌더된 폭을 재서 `rem`으로 바꿨다 |
| 파비콘이 깨졌는데 HTTP 검사는 통과했다 | 200에 올바른 Content-Type이라 통과로 보였지만 `<img>`로 그려보니 깨져 있었다. XML 주석 안에 붙임표 두 개(CSS 변수 이름)를 쓸 수 없다. 정상 응답과 유효한 내용은 다른 사실이다 |
| 저장소 자기 규칙을 과제 요건인 것처럼 써서 후보를 죽였다 | "설명할 수 없는 코드는 채택하지 않는다"는 작업 규칙인데, 그걸 근거로 웹폰트를 재보지도 않고 접었다. 실제 기준은 "설명할 수 있는가" — 배우라는 요구다 |
| 근거가 순환이었다 | "쓰는 아이콘이 다섯뿐이라 패키지가 필요 없다" — 손으로 옮겨야 하니까 적게 쓴 것인데 그 결과를 근거로 삼았다. 패키지를 깔자마자 같은 아이콘 두 곳을 고쳤다 |
| 비교할 수 없는 두 수를 나란히 놓고 결론을 냈다 | "1.7MB가 비싼데 2MB 글꼴이라니" — 앞은 매 요청이고 뒤는 한 번 받고 캐시된다. 단위가 다른 두 수가 나란히 있으면 문장이 그럴듯해진다 |
| 활자만 갈아입히고 "개편했다"고 했다 | 참고 화면의 인상을 활자로 오해했다. 진짜 차이는 사물이 화면을 차지한다는 것이었는데, 우리 화면은 사진이 56px이고 옆 글자가 더 컸다 |
| 배운 것을 다른 화면에서 다시 밟았다 | 사진 틀의 비율 고정을 뺐더니 열두 장이 점으로 접혔다. 같은 교훈("사진이 오기 전에도 칸 높이가 있어야 한다")을 v1 격자에서 이미 배웠었다 |
| 3D 봉투가 클릭을 못 받는데 화면은 멀쩡해 보였다 | `elementFromPoint`로 재보니 z=0의 부모 평면이 히트를 다 먹고 있었다. translateZ가 음수인 자식은 평면보다 뒤다 |
| 드래그를 놓는 순간 오류 화면으로 떨어졌다 | `setState` 업데이터가 지연 실행되며 null이 된 `ref.current`를 읽었다. 지역 상수로 캡처해 잡았다 |
| 닫힌 봉투의 첫 안이 깨진 렌더링처럼 보였다 | 편지 첫 줄을 내놓는 안은 뚜껑이 글자를 대각선으로 갈랐다. 줌 캡처로 보고 접었다 |
| 브랜치 없이 main에 커밋하고 푸시까지 했다 | 이슈→브랜치→PR 규칙 위반. 커밋을 브랜치로 옮기고 main을 되돌려 PR로 재진입했다. 두 번째에는 푸시 전에 잡았다 |
| 포커스 링을 고치려다 버튼을 네모로 만들 뻔했다 | `outline`은 이미 요소의 반지름을 따라간다. `border-radius: inherit`을 더하면 포커스 순간 부모의 반지름(0)이 된다 |
| v2에서 화면을 옮기고 자리를 안 옮겼다 | 데모 초기화의 자리 근거가 "첫 화면의 맨 아래"였는데 첫 화면이 바뀌자 옛 홈에 남아 있었다. 홈이 다시 바뀌었을 때는 같은 실수를 첫 커밋에서 막았다 |
| 같은 것을 두 화면에서 그리고 있었다 | 책 줄이 두 화면에서 렌더됐다. 한쪽에서 만든 책이 다른 쪽에 안 보이면 어느 쪽이 진짜인지 물어야 한다 |
| `display: none`을 썼는데 안 숨었다 | 같은 특이도의 `display: inline-flex`가 파일 뒤에서 이겼다. 선택자를 한 단계 올려 잡았다 |
| `euc-kr` 코덱이 KS X 1001이 아니었다 | 완성형 2,350자를 그 코덱으로 걸렀더니 11,172자가 전부 통과했다. 그 코덱은 CP949다. 바이트 구역을 직접 훑고, 2,350이 아니면 실패하는 검사를 박았다 |
| 값이 하는 일이 늘었는데 그 화면이 침묵했다 | 생일 입력이 캘린더의 검진 창까지 만들게 됐는데 화면은 옛 역할만 설명했다. 사용자는 왜 비었는지 모른 채 빈 달력을 본다 |
| 문서가 자기 화면을 잘못 가리켰다 (4곳) | 화면을 세 번 갈아엎는 동안 문서의 화면 서술이 낡았다. 첫 화면·버튼 위치·문구 인용이 전부 개편 전 것이었다. 화면을 고칠 때 그 화면을 서술한 문서를 같이 찾아야 한다 |
