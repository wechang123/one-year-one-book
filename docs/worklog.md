### 10:10 인프라 이식
Dockerfile · docker-compose · entrypoint · Prisma 연결을 직전에 검증해둔 것에서 그대로 옮겼다.
검증이 끝난 것을 다시 만들 이유가 없다. 이름만 치환.

**직접 내린 판단**: `next.config.ts`에 `serverActions.bodySizeLimit`을 8mb로 뒀다.
기본값이 1MB인데 폰으로 찍은 사진은 2~5MB다. 이 설정이 없으면 **업로드가 오류 없이 조용히 실패한다.**
이 서비스는 사진이 콘텐츠라 그 실패가 곧 서비스 전체의 실패다.

### 10:14 ❗ AI가 자기가 어제 발견한 것을 다시 어겼다

**무엇이 문제였나**
스키마를 새로 쓰면서 `datasource db { url = env("DATABASE_URL") }`를 넣었다.
Prisma 7부터는 이게 금지다 — 연결 문자열은 `prisma.config.ts`가 맡는다.

**어떻게 발견했나**
Docker 빌드가 `npx prisma generate`에서 실패했다. 에러 코드 `P1012`.
로컬에서 재현하려 했더니 `node_modules`가 없어서 다른 에러가 났고, **컨테이너 빌드 로그를 직접 다시 잡아** 원인을 확인했다.
`grep`으로 "error"만 걸러서는 안 나왔다 — 빌드 로그는 실패 라인만 요약해서 보여주기 때문에 **해당 스텝의 전체 출력**을 봐야 했다.

**왜 일어났나 — 이게 핵심이다**
어제 **정확히 이 문제를 이미 겪었고**, 커밋 메시지에 이렇게까지 적어뒀다.

> *"Prisma 7은 스키마에 url을 둘 수 없다 — 연결 문자열은 prisma.config.ts가, 실제 연결은 어댑터가 맡는다."*

그런데 새 저장소에서 스키마를 **처음부터 다시 쓰면서** 그 기록을 참조하지 않고 관성대로 썼다.

**교훈**
검증된 설정을 옮길 때는 **다시 쓰지 말고 복사해야 한다.** 인프라 파일은 그대로 복사해서 문제가 없었고,
유일하게 손으로 새로 쓴 파일(`schema.prisma`)에서 사고가 났다.
"이 정도는 기억한다"가 가장 비싼 가정이다.
